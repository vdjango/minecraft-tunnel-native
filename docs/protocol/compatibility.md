# 连接恢复与兼容

## 目录、选路与活动会话

| 阶段 | 当前行为 | 接入方处理 |
|---|---|---|
| 导入节点 | 验证固定公钥与凭据，可带最多 5 个备用配置 | 预先保存可信入口，离线时不能凭空发现节点 |
| 目录失败 | 只读操作最多尝试 3 个缓存入口；写操作不自动重放 | 不要盲目重试建房、设置或好友写操作 |
| 选路刷新 | 更新之后新连接的入口 | `node.selected` 变化不代表活动游戏已切换 |
| 首次建房/加入失败 | 返回启动错误/超时，不留下持续后台重连任务 | 显示错误，更新入口或邀请后重新创建 |
| 活动会话 SSH 故障 | 清理旧流与监听，进入 `reconnecting`，用创建时的候选重建 | 轮询 `session.events` / `session.list`，使用重建后的地址与状态 |
| 备用持续失败 | 最多 6 次延迟重试，依次 1/2/4/8/10/10 秒，每轮可尝试多个候选，连接耗时另计 | 最终 `stopped`、原因 `backup-unavailable`，提示重新探测/更新接入码 |
| P2P 故障但 SSH 健康 | 释放该玩家 P2P 流，新游戏连接可使用中继 | 已建立 TCP 会断开，玩家需要重新加入 |

重试次数针对连续建连失败，成功重建会重置计数。活动会话候选不是实时拓扑订阅，不能假设新发现的节点已加入其备用集合。正常关闭或房间明确结束不应作为节点故障反复重建。

## 启动器缓存

Buggcraft 启动器在本地缓存最多 32 个入口；拓扑刷新为空或失败时保留最近有效结果，向桥传入受限候选。其他启动器需自行实现持久缓存。32 不是桥实例的节点句柄数量上限。

缓存含地址、固定公钥和凭据，应按凭据保存。历史缓存不能绕过密钥轮换、令牌过期、隔离或网络不可达。所有备用均失效时，停止有界重试，从可信渠道更新接入码；不要关闭公钥或证书校验。

## 联邦不能替代会话复制

联邦没有一致性选主、TCP 状态复制或存档托管。房主桥可在候选上重建房间，访客须连接实际归属节点；双方独立重试不保证一次选中同一节点。分区或归属歧义时也不能承诺自动恢复。

SSH 故障会清理该会话的 P2P 和游戏流，即使先前直连仍能交换数据。旧 SSH/TCP、游戏登录状态和聊天历史不能跨节点迁移。详见[联机流程图](../launcher-federation-flow.md)和[传输协议](transports.md)。

## 混合版本

- 能力以 `bridge.initialize.methods/limits` 和目录 `ping.capabilities` 为准，不能只看网页日期或文件名。
- 公开邀请房间要求 `room-invite-policy-v1`；旧节点缺少能力时停止创建，不能降级为无邀请保护。
- 准备状态、成员管理与安装日志授权要求 `room-lobby-v1`；旧节点可保留基本游戏连接，但隐藏不支持的管理操作，不能将未收到成员快照视为全员就绪。转让后 `manager_id` 与 `provider_id` 可能不同，不能继续仅凭 SSH 的 host 角色授予管理权。详见[准备房间协议](room-lobby.md)。
- 旧公告缺少 `statistics.players` 时退回公开房间 `members` 之和，私密房间会漏计；旧节点不支持 `online_players` 时详情为部分可用。
- 缺少 `game` 或预览表示未提供，不能判定完全匹配；完整清单另走[模组接口](game-metadata.md)。
- P2P 应用心跳先协商能力，旧桥仍依赖 ICE/SCTP，不能套用新心跳的超时保证。
- 原自定义二进制包头、PacketType、主从注册与 Raft 文档不对应当前实现，不能照旧构造消息。
