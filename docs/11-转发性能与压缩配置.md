# 转发性能与压缩配置

节点配置文件是持久化目录下的 `server.conf`，由 `web/main.py --config 路径` 读取；首次网页初始化生成该文件。参数示例见 [config.example.ini](../config.example.ini)。修改已有 `[relay]` 项，不要用示例覆盖完整配置、账号、身份或 Web 设置。

## 默认关闭额外中继压缩

```ini
[relay]
compression = off
```

`off` 使用原始游戏流，关闭原生桥两端额外的 Zstandard 编解码；节点不宣告 `relay-zstd-v1`，拒绝新压缩监听/压缩流。已有桥、SDK 或启动器即使请求 `compression: "auto"`，在此节点上也使用未压缩中继，不需要各启动器再实现一套配置。

SSH/WebRTC 加密与完整性校验保持启用，Minecraft 自己的协议压缩保持原有配置。此开关仅作用于 SSH relay 的 BCZ1 扩展，不修改 P2P DTLS/SCTP 或 Minecraft 的 `network-compression-threshold`。

新初始化配置与省略此项时均默认 `off`；已有文件显式写了 `auto` 则继续按其配置运行，要关闭需改为 `off`。程序不会静默重写用户配置。配置在下次节点启动读取，不支持热重载；安装包可在无人联机时执行 `sudo systemctl restart buggcraft-node`，重启会中断现有会话。源码部署重启自己管理的节点进程。

## 按需选择 auto

带宽受限且载荷仍可压缩时，可明确开启：

```ini
[relay]
compression = auto
```

节点、房主桥和访客桥均支持时才协商压缩；桥显式 `compression: "off"` 仍可拒绝。阈值和降级规则见 [中继压缩扩展](20-协议规范/07-中继压缩扩展.md)。公网应根据吞吐、小包 P99、CPU 及实际编码字节选择。

此前“无压缩前后 +6.4%/+20.9%”比较的是同一策略下旧/新加密选择，不能推出关闭压缩更快。两组负载实际发送比率不同，高度重复测试数据也不代表真实游戏流量。[实测报告](30-性能报告/03-20261110-游戏转发与加密指令集.md)保留这一边界。默认 off 是按需求减少额外计算，不承诺任意网络都提速。

## 验证生效

重启后新建房间、连接访客：目录 `ping` 不包含 `relay-zstd-v1`，桥日志 `game_path` 应为 `path: "relay"`、`compression: false`；完成载荷校验和 EOF 才说明转发正常。SSH cipher 仍存在，关闭压缩不等于关闭加密。P2P 本来就不走此扩展，不能用其成功判断中继设置。

```bash
python -m unittest \
  tests.test_native.NativeTests.test_compression_default_off_and_explicit_auto_negotiation \
  tests.test_bridge.BridgeTests.test_node_compression_off_forces_raw_bridge_forwarding_and_eof -v
```

线程数、Ring 容量继续由 [部署配置](03-节点部署与配置.md) 与 [性能验收](09-性能测试与验收.md) 维护，不为这个开关复制第二份运行配置文件。
