# 节点安全边界

本文描述当前源码行为，不能代替对实际部署配置的检查。客户端必须固定校验节点 SSH 公钥。节点按目录、房主、访客和联邦角色验证相应凭据：玩家使用节点访问授权，房间访问另校验密钥，个人账号与联邦各有签名校验；管理员 HTTPS 会话与玩家凭据独立。

## 转发与游戏过滤

SSH shell、exec、SFTP、任意目的地址、公开反向监听和未授权房间转发被拒绝。访客只能访问当前房间房主申请的监听；访客本机游戏地址只监听回环。节点、房间与客户端仍需配置连接、流数量、带宽及请求限额，认证成功不等于可以无限消耗资源。

房主原生桥在将访客有效载荷写入本机游戏 socket 前检查首个 Minecraft Handshake：包长 6–8192 字节、包 ID 0、主机名最多 255 字节、端口与下一状态（1 或 2）完整，并验证 VarInt 与握手包边界。P2P 与中继均进入房主流处理，桥传输压缩先解码再检查。合法握手后可以紧接后续数据，不能把一次读取中的剩余数据一律判非法。

原生桥对未完成握手设 10 秒期限；Python 中继兼容路径的超时在收到数据时检查，不等同于主动空闲定时器。C++ 节点转发核心本身不等于房主桥的应用层检查。桥可能先建立本机 TCP 连接再拒绝有效载荷，因此不能承诺本地服务完全收不到连接。

这不是完整 Minecraft 防火墙：通过后不持续检查所有游戏包，攻击者可构造合法开头，游戏本身也可能加密。修改过的房主桥还能绕开自身检查；不能把它当成向任意本地服务提供访问的安全代理。

## 网页、代理与联邦

公共导航不显示后台入口，真正边界仍是管理员会话、权限、HTTPS、Origin 与 CSRF。知道 `/admin` 或 `/diagnostics` 不应获得管理数据；隐藏路径不等于授权。账号登录不能访问管理员日志或节点配置。

Cloudflare 网段自动获取并缓存，手工列表仅用于额外可信代理。只有 TCP 对端受信时才使用 `X-Forwarded-Proto` 和有效的 `CF-Connecting-IP`；拒绝 `0.0.0.0/0` 与 `::/0`。可信代理必须覆盖客户端伪造的转发头，源站防火墙仍需运营者配置。更新周期见[部署指南](deployment.md)。

联邦签名认证来源，不保证成员诚实；入网密钥泄露后，仅封禁单个 ID 不能阻止换身份重入。全网在线总数包含私密房间会话；登录后的在线详情可见昵称及脱敏房间名，不能当作匿名系统。模组 SHA-256 只证明与房主清单一致，不证明 JAR 安全，启动器仍需用户确认下载和覆盖。

## 部署与凭据

安装包 service 模板使用专用用户、`NoNewPrivileges`、只读系统、私有临时目录、设备/地址族限制与 `0700` 状态目录。已有自定义 unit 不会因源码模板改变就自动生效，应使用 `systemctl cat buggcraft-node` 和 `systemctl show buggcraft-node` 核对。

这项检查是协议入口过滤器，不能保证 Minecraft 服务端没有漏洞，也不能识别所有应用层恶意包。不要把房主的 Minecraft 本地端口直接暴露给 Internet；防火墙只开放维护 SSH、节点服务和 Web 入口，节点之间使用已知公钥。运行 Minecraft 服务端的实例仍应及时更新、关闭不需要的插件并使用游戏自身的白名单/权限。

本实现拒绝没有有效凭据的第三方桥；持有有效凭据并实现相同协议的第三方仍能通信，服务端无法据网络数据证明官方二进制。固定嵌入密钥可以被提取。当前发行包 SHA-256 是完整性校验，不能称为代码签名或来源认证。

泄露后按类型轮换节点访问授权或房间邀请；共享联邦入网密钥失守需可信运营者协调重建信任，单节点隔离不会撤销全网玩家凭据。检查认证失败、流拒绝和资源耗尽记录，不能将日志缺失当作无攻击。P2P 会向对端暴露网络候选地址，有地址隐私要求时选仅中继。详见[部署指南](deployment.md)与[协议概览](protocol/overview.md)。
