# 生命周期与状态契约

以下记录现有所有权及修改时必须保持的约束。完整字段、错误码和状态枚举继续以领域协议为准，不在此复制另一份协议。

| 对象 | 所有者/线程 | 结束与失败 |
| --- | --- | --- |
| Engine / Worker / Peer / Stream | Engine 创建工作线程；房间亲和迁移由既有 worker 调度，命令经 `post` | 移除流后移除 peer，清理待回复 RPC；保持背压与 EOF，不能通过丢弃排队字节提升吞吐 |
| Python NativeRelay 与子进程 | `web/tunnel/native_relay.py` 事件循环 | 进程退出触发已有断连/服务恢复流程；IPC 上限仍有效，游戏字节不进入 Python |
| ControlPlane / 社交发送队列 | Portal 事件循环，唯一后台任务；Federation 拥有连接池 | 先取消 ControlPlane 再关闭联邦连接池；每轮至多 4 条，到期清理，取消不丢磁盘队列；本地先保存、远端持久确认后移除，临时存储错误不得当作业务拒绝 |
| Social 设备心跳与持久事件 | Accounts 拥有 Social，签名由现有账号验证 | 心跳按账号/设备公钥分开，20 秒失效为 unknown，不从磁盘恢复在线；关系/邀请/申请/队列保存在同一版本化文件，旧版回退须恢复备份 |
| 桥 Rpc / Session | CLI 和 C ABI 都用 Rpc；Session 工作线程持有网络状态 | 请求投递既有命令队列；关闭、重连及异步回调遵循会话生命周期，不能让迟到回调复活已关闭会话 |
| C ABI handle / response | 同一句柄调用加锁，不同句柄可并行；调用方负责句柄生命周期 | 不与 destroy 竞争；响应必须调用 `buggcraft_bridge_free`；句柄、响应全部释放前不能卸载库 |
| Winsock/libssh/RTC 全局运行期 | `acquire_runtime/release_runtime` 的互斥引用计数 | 首次初始化、最后释放；SDK 消费方不另设第二套引用计数 |
| Stream / Codec / Ring | Session 管流、流持有缓冲和可选 Codec | 半关闭先排空再 EOF；坏帧、窗口超限、截断必须失败；双向缓冲与公平调度有界 |
| ModTransfers::Transfer | ModTransfers 持有下载记录、临时文件和逐任务摘要 | 字节数与 SHA-256 一致才提交；失败/取消删除临时文件；已有目标只需 SHA-256 时不额外计算 SHA-1 |
| Digest / SIMD 字节扫描 | 摘要上下文归单次调用线程；扫描无外部副作用 | EVP 失败抛异常；文件 badbit 不得当正常 EOF；扫描不越界；分派首次使用后固定 |
| Base64 codec / stream state | 函数表由 C++ 线程安全静态初始化发布后只读；流状态在每次调用栈上 | 不调用上游公共 API 的可变全局分派；不让 SDK 不同句柄共享 carry、eof 或输出缓冲 |
| SSH CipherPolicy | 首次 Ssh 连接时由 C++ 线程安全静态初始化发布；之后所有 CLI/SDK 会话只读 | 输入是进程启动前的策略环境及当前 EVP 成本；合成数据探测在调用线程同步完成且仅一次，EVP 上下文 RAII 释放，不持有会话密钥；失败保留库默认算法，应用偏好由 Ssh 所在线程在 connect 前完成 |
| 页面 scope / views | `createScope` 管异步资源，`createViews` 管子视图挂载 | `dispose` 中止请求、清除定时器/监听并恢复 exposed 值；页面卸载时 views 同步释放 |
| 页面 DOM / seed | Vue 页面/共享组件为 UI 源码，服务端 seed 来自真实响应 | 等待/错误/空值真实显示；不把未知延迟显示成 0；DOM 变化同时检查控制器选择器和清单 |

改公共方法时说明参数、返回值、失败、线程、资源所有者以及取消后晚到结果如何处理。摘要/编解码等同步计算不能伪称可取消；新增长任务必须接入所属模块的取消与队列规则。本文不承诺尚未实现的无锁、零拷贝、自动故障复制或跨线程 API 安全。

受管适配：RelayPortal 事件循环拥有 ManagedControl 与有界 aiohttp 会话，关闭先取消心跳再释放 HTTPS；诊断 writer 保持到原生 relay 断连记录完成。IdentityPortal 仅在控制主机运行，不启动原生 relay、联邦或社交任务，HTTP 请求排空后释放 IdentityAuthority 会话；账号与设备各有唯一持久所有者。节点断线预留宽限 60 秒，旧 peer 的迟到 disconnect 不能删除新预留。桥 ControlClient 由 Rpc 与 Session 回调共享持有，递归互斥量串行化刷新和预留表；Session 关闭后释放房间预留。HTTPS 同步调用仅在原生桥工作线程，最长十秒，不在 Qt GUI 线程。见[12](12-统一控制与稳定性.md)、[13](13-服务精简与复用验收.md)。

新增回调先查现有 Session、Rpc、scope 或 Transfer 是否已经持有该操作，优先向原所有者提交。共享编码只处理字节与格式；接入码有效期、认证、路径约束和大小限额仍由原业务域执行。

受管节点选择补充：ControlClient::probe_candidates/routes/select_route 复用现有 HTTPS 候选、SSH 探测及服务器签名测量票据。候选快照最多采用控制服务返回的有界候选；探测仅在桥工作线程，每个连接两秒超时，缓存三十秒。手动偏好只约束新房预留，加入房间仍跟随房主；单个候选不可达返回明确错误，不冒充零延迟。探测值是建立 SSH 连接耗时，不等于纯网络往返。Rpc 的 CLI/C ABI 接口共用该唯一所有者。地区不足以唯一标识节点时，大厅不嫁接其他节点的延迟样本。

Session 的 node_name_ 与 status() 快照由原互斥量保护，建立及重连成功时更新；到节点使用原 node-latency 应用回显，到房主使用原 latency 及成员 rtt_kind，不新增游戏数据路径或测量协议。Qt 的迟到响应使用 node handle 和代次丢弃，换 handle 清理旧 nodesBusy，界面切换不释放仍在运行的房间。

2026-11-12：成员可同时携带 node_rtt_ms/host_rtt_ms，复用已有回显、Minecraft ping 与 P2P 心跳，不新增探测线程。RoomLobby 独立保存线路采样的 _path_seen，不用准备进度的 _seen 延长旧 RTT；离线或过期清空两值。此节点控制层仍属待原生化实现，不据新增 JSON 字段宣称完成节点 C++ 迁移。

文件调度由同一 ModTransfers 所有：`set_wakeup(callback)` 仅在绑定任何文件通道之前设置，回调可从 RTC 线程调用，只通过弱 Session 引用通知现有 Wakeup，不执行文件或 SSH 操作。`tick(Ssh&)` 和 `poll_timeout_ms()` 仅由 Session 线程调用；前者限制每条 P2P 文件流每轮的消息数/发送字节数，后者返回下一轮允许的最长等待（0–50 ms），处理已排队消息和上传令牌到期。游戏流先于文件批次处理。保留独立文件 PeerConnection、原有窗口、授权、摘要、取消和 EOF 契约；批次上限不是磁盘单次 I/O 的耗时保证。
