# 20261110 控制中心原型与故障隔离验收

状态：未发布的 Python 行为原型，未替换生产服务。用户后续明确要求[独立 C++ 控制服务](../../../buggcraft-control-native/docs/00-规划总览.md)、长期可复用的接入凭证及大规模地区调度；原型的短期票据和共享联邦密钥方案不再作为最终方案。保留验证证据，不宣称 C++ 服务已经实现。

## 已验证行为

Windows 完整相关套件 96 项通过（373.673 秒），包含原生节点/桥/SDK、社交、在线、联邦预算/查找/规模、中心行为与原有引导节点故障隔离。Linux 隔离目录 51 项通过（10.566 秒），包含当时的 11 个中心用例及社交/联邦相关回归。Windows 兼容套件 27 项通过（163.329 秒），覆盖网页账号、身份副本、联邦签名完整性和 SSH 权限。

这些数量对应各次套件当时的测试输入；后续新增用例不自动计入上述通过数。另一个备用入口/业务拒绝用例独立通过（4.296 秒），不重复计入上述套件，结果保存在原始证据目录。最初几轮调试日志仍保留，但不计作通过。

实际链路为测试机回环上的独立 C++ 原生节点、桥及 HTTP/HTTPS 管理会话。Windows 和 Linux 各自做真实进程/载荷测试，不是 Windows 与 Linux 两机之间的公网联机验证。Linux 使用已授权服务器的隔离临时目录，无生产重启或覆盖。

中心协调了两个工作节点的好友申请、接受、房间邀请、加入；随后终止中心原生进程，继续从工作节点进行 1 MiB 随机游戏载荷回声与 EOF 校验。该结果证明本原型选用的房间中继路径不依赖中心持续转发，不能证明中心存储机损坏时账号/消息已自动高可用。

另外覆盖：固定 SSH 公钥、短期票据单节点绑定和同节点重试、HTTPS 证书固定、管理员/CSRF、未授权发行者拒绝、发送队列重建与 TTL、磁盘写入失败不误确认、多设备在线/离线/unknown、原有联邦公平预算及签名验证。

## 复用与实现边界

原型复用 Federation 的签名记录/固定公钥连接池、Portal 的管理员/CSRF/原子写入、Social 的用户签名及房间管理者校验。新增 `social_delivery` 为网页/桥/SDK 共用投递入口，`ControlPlane` 为原型模式/入网/后台任务所有者；没有改 C++ 游戏密码或复制另一套转发核心。

原型持久好友文件变为版本 2；旧版本回退须恢复完整备份。默认模式仍为 mesh。未更改现有用户的身份复制授权，没有把账号密文自动集中到中心。未完成新 C++ 控制服务、长期公共接入、分区容量调度、数据库高可用和公网大规模压力测试，也没有新的 ISA 或游戏吞吐成绩。
