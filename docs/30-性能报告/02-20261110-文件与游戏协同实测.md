# 转发与启动器联机协同优化实测

测试日期：2026-11-10（北京时间）。本轮针对文件下载时的游戏小包延迟，以及新版启动器的联机请求排队。之前的 CPU 指令集对照继续见[性能实测报告](01-20261110-跨架构与CPU实测.md)，本轮没有新增或改变 ISA 分派。

## 结论

同机、同输入、前后实现交替三轮，四个文件合计 64 MiB 下载期间，游戏回声 p99 的三轮中位数：Windows **94.61 → 4.27 ms**，Linux **107.29 → 2.76 ms**。每轮文件 SHA-256、游戏回声、双向 EOF 和实际 P2P 路径均通过。这里是本机网卡地址上的真实原生进程/P2P 测试，不是跨公网测试或 Minecraft GUI 帧率测试。

文件限额为 10240 KiB/s，即 10 MiB/s。旧实现初始授予一秒上传额度，短测试测得约 11.8 MiB/s；新实现限制突发后稳定在约 10 MiB/s。因此本轮改善的是下载期间的交互延迟和速率节奏，不能描述成“文件下载更快”。

新版启动器的空事件处理不再修改快照或发 changed；交互请求可以越过尚未发送的后台刷新。同级 FIFO、已发送请求不抢占。真实隔离节点验收覆盖授权、刷新期间更新节点句柄、好友、准备房间、私密/公开配置、聊天、取消及重新建房。

## 实现与复用

检索 `core/relay.cpp`、`Worker::run`、`Session::tick/run/pump/post`、`ModTransfers::tick/pump_peer/bind_peer_channel`、`NativeBridge::call/dispatch/receive/fail`、`MultiplayerService::refresh/heartbeat/apply_room_events`，并核对旧版 `native_routes/native_transport` 的调用格式。

审计修正：文件实体在现有实现中已经使用独立文件 PeerConnection，并禁止 SSH 回退；SSH 传递的是清单元数据。本轮保留这项隔离，没有再增加第二套文件连接或绕过文件授权。

- 原生桥/SDK：游戏流先于文件批次处理；每条文件流每轮最多消费四条消息或发送 64 KiB，保留 256 KiB 在途信用窗口。接收队列、通道打开/关闭、低水位事件通知现有 Session Wakeup；已排队的下一批立即继续，等待上传额度时按补充期限唤醒，最长仍为 50 ms。复用现有 RTC、Ring、速率桶、摘要与文件提交，不增加转发线程或协议副本。
- 文件上传：原有共享速率桶改为约 25 ms 的突发额度，容量下限一个 16 KiB 块、上限 256 KiB；不为不足一个完整块的剩余额度产生大量碎片。每个发送块同时受接收信用余额约束。保留原有轮转服务顺序。
- 启动器：在 NativeBridge 唯一有界队列上增加 Interactive/Background，定时 presence、目录/好友刷新及 session.list 使用后台级；用户命令和房间事件仍为交互级。换节点句柄后丢弃旧句柄的后台结果，避免请求重排后把过期错误写回。空事件不再更新整份房间/消息快照。
- 验证：扩展现有 `bridge_soak.py --scenario mixed`、BridgeServicesTests、runtime_test 和隔离节点夹具；没有复制 SDK 或网络状态机。夹具通过 `BUGG_TEST_BUILD_DIR` 选择独立构建目录。本轮未修改 QML/DOM，也未调整另一窗口的实例扫描、下载或渲染优化。

原生方法/源码清单已重新生成；启动器方法索引、共享接口和方法参考已同步。生命周期契约记录新回调的线程和释放规则。

## 方法与环境

| 项目 | Windows | Linux |
| --- | --- | --- |
| CPU | i9-10850K，10 核/20 线程 | AMD EPYC 7K62，4 vCPU |
| 系统 | Windows build 26100 | Ubuntu 24.04，glibc 2.39 |
| 原生构建 | MinGW GCC 15.2，Release/LTO | GCC 13.3，Release/LTO |
| OpenSSL | 3.5.2 | 3.0.13 |
| 启动器 | MSVC 19.44.35219、Qt 6.8.1、Release | 本轮未构建 Qt 启动器 |

每轮建立独立测试节点与房主/访客原生桥，游戏和文件均确认直连；四个确定性伪随机文件各 16 MiB，先用小文件完成独立文件连接协商，再计时大文件下载。游戏连接先发送 Minecraft 握手，再循环发送 64 字节回声探测，探测之间请求休眠 10 ms。它是闭环发生器，不保证严格固定探测频率；新实现的探测响应更快，样本数也会增加。

三轮顺序为 before/after、after/before、before/after。同一平台复用相同节点核心和依赖，替换桥实现；CPU 硬件加速、压缩和文件限额一致。文件数据准备和建房不计入下载耗时。文件来自暖文件缓存，网络为同机网卡地址；后台桌面/共享云主机负载未被关闭，尤其 Windows CPU 数值存在明显离散。

性能驱动明确关闭 asyncio debug；普通回归仍保留 unittest 原来的调试默认，两者不能混为性能结果。保存了基线可执行文件、参与文件的修改前副本、二进制/源码/原始结果 SHA-256、JSON 和逐进程资源采样。

## 三轮结果

以下为三轮中位数，方括号为最小–最大。p99 是先计算每轮的探测 p99，再汇总三轮；不是把所有样本合并后重算。

| 指标 | Windows 修改前 | Windows 修改后 | Linux 修改前 | Linux 修改后 |
| --- | --- | --- | --- | --- |
| 游戏回声 p99，ms | 94.61 [67.26–97.05] | 4.27 [4.01–4.36] | 107.29 [106.73–163.78] | 2.76 [2.68–2.81] |
| 每轮最大 RTT，ms | 117.30 [97.89–162.37] | 8.13 [6.79–10.86] | 296.56 [244.37–371.10] | 10.98 [3.96–11.25] |
| 文件吞吐，MiB/s | 11.80 [11.77–11.80] | 10.03 [10.02–10.03] | 11.79 [11.77–11.80] | 10.01 [10.00–10.01] |
| 原生进程峰值 RSS，MiB | 69.21 [69.00–69.64] | 66.76 [66.50–66.81] | 71.91 [71.08–72.58] | 59.30 [59.17–60.04] |
| 采样原生 CPU，秒 | 14.95 [14.14–15.36] | 19.63 [8.27–20.69] | 9.71 [8.97–9.74] | 8.83 [8.78–8.91] |
| 三轮合计 >100 ms 探测 | 4 | 0 | 19 | 0 |

CPU 秒数由资源 JSONL 中原生进程的累计 user+system 时间汇总，包含协商和清理，不只下载阶段，采样不是精确的退出时进程核算。Windows 修改后中位数增加且范围很大；没有证据声称本轮节省 Windows CPU。文件传输时间变长、探测数量不同及后台负载均影响总 CPU，不能由本表直接推算每字节成本或服务器最大玩家数。

启动器空事件微基准：同一含 200 条消息的快照，调用 25000 次，交替三轮。旧实现中位数 **15.863 ms [14.348–16.541]**，新实现 **0.135 ms [0.135–0.135]**；changed 从 25000 次变为 0，前后快照一致。这个量级仅证明消除了无效状态通知，不代表启动器整体快了百倍，也不承诺游戏 FPS 改善。

## 正确性与接线验收

- Windows：原生 CTest 4/4；桥服务、共享库、重连、心跳/单向 UDP 丢失恢复共 41 项通过；新增低速率突发回归在 CLI 与 SDK 各 1 项通过。包含并行文件下载期间游戏交换、授权拒绝、摘要错误、取消不发布半文件、任务槽位释放、混用 CLI/SDK、ABI 并发与隔离安装。
- Linux：原生 CTest 4/4；相同 41 项中 36 项通过、5 项跳过，另 CLI/SDK 速率回归 2 项通过。五项缺口为旧版启动器源码相关测试四项，以及未安装完整包的搬迁测试一项，不计通过。
- 新版启动器：直接相关 Qt 回归 27 项通过，无跳过；覆盖新增排序/空事件、真实消息和路径更新，以及原有授权、内容准备、缓存、取消、实例锁定和游戏启动参数。
- 同一新版启动器＋本轮桥＋隔离真实节点：HTTPS 设备授权与精确请求批准、旧后台请求期间更新节点句柄、好友、房间配置/聊天/取消/重建通过。使用本轮独立安装的原生运行目录，不依赖历史随带引擎。
- Windows UIAutomation 检查未发现防火墙提示窗口；核对了当前构建核心/桥的已有 Public 入站允许规则。未关闭防火墙，也未把规则存在当作跨公网验收。

## 重现入口与边界

```powershell
$env:BUGGCRAFT_NATIVE_CORE = '<同一版本核心绝对路径>'
$env:BUGGCRAFT_BRIDGE_EXECUTABLE = '<before 或 after 桥绝对路径>'
python scripts/bridge_soak.py --scenario mixed --file-mib 16 --output validation-artifacts/mixed.json
python -m unittest tests.test_bridge_services tests.test_bridge_library tests.test_peer_reconnect tests.test_peer_heartbeat
python scripts/update_code_inventory.py --check
```

Linux 使用相同脚本，设置对应 ELF 路径和依赖库搜索目录。至少三轮交替替换桥实现；不能将旧桥错误地链接到不同加密库。SDK 使用同一 engine，另设置 `BUGGCRAFT_BRIDGE_LIBRARY` 为实际共享库路径。

新版启动器使用独立构建目录执行 runtime_test；设置 `BUGG_TEST_BUILD_DIR` 后运行 `tests/integration/node_approval_fixture.py`，`BUGG_TEST_NODE_ROOM_FLOW=1` 验证房间流程，`BUGG_TEST_NODE_RENEW_QUEUE=1` 验证句柄更新期间的后台回复隔离。该夹具只批准独立测试账号请求。

本轮没有重跑真实 Minecraft GUI、直接公网、macOS/ARM64 性能，也没有执行限带宽＋固定 RTT＋随机丢包的完整矩阵。已有公网与 GUI 结果属于前一份报告，不能作为本轮修改后的证明。文件磁盘 I/O 仍在 Session 线程，批次有界不保证慢盘延迟有界；进一步拆分异步文件 I/O、调优高 RTT 信用窗口和大连接数事件机制需要另做针对性测量。

原始证据位于本地 `validation-artifacts/forwarding-20261110/`；`summary.json` 保存聚合，`provenance.json` 保存来源及校验。生产节点未替换、未部署；Linux 构建和负载只使用原独立测试目录。
