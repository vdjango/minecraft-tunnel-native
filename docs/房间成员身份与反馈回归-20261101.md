# 房间成员身份与反馈上传回归（2026-11-01）

## 对接字段

`room-lobby-v1` 的 `members` 快照继续按稳定 `id` 标识玩家。本次增加可选 `account_name`：由节点根据认证账号查询名称生成，客户端 `member_update` 不能设置或覆盖。未绑定个人账号时为空。`name` 仍是该成员自行上报的游戏角色名，不能当作认证账号标识；账号名也只是可修改的展示信息，不是权限凭据。

```json
{
  "id": "stable-member-id",
  "name": "MinecraftRole",
  "account_name": "NodeAccount",
  "state": "playing",
  "manager": false,
  "provider": false
}
```

启动器以 ID 更新现有行，主行展示游戏角色，账号不同时在副行标明；旧节点不提供新字段时不影响成员显示。`starting/playing/ready` 由对应实例的真实进程状态上报，不根据玩家是否进房猜测，也不读取首页后来切换的账号冒充正在运行的角色。

## 反馈上传

线上旧部署的 Python `NativeChannel` 缺少 `pause_reading/resume_reading`，反馈上传读取首行时即异常。当前控制层通过 `channel_read_pause` 驱动 C++ 流量控制；部署时必须使用匹配核心与 Python 控制层。此接口的幂等回归加入 `tests/test_member_identity.py`，大文件慢磁盘/其他控制请求测试见 `compatibility/tests/test_feedback_native.py`。

两台生产节点均更新了匹配的核心、其依赖库和两份控制层文件，保留原节点数据及网页资产。启用前以实际服务用户与现有 SSH 主机密钥启动独立端口预检，再原子切换 release；失败恢复原 release。最初直接复制构建目录的二进制因 systemd PrivateTmp 无法访问构建 RPATH 而预检失败，已经回滚；最终改用 CMake 安装产物及 `$ORIGIN/../lib`，预检和健康检查通过。

81.68.225.236 当前为 `room-experience-20261101-r2`；43.241.50.19 当前为 `room-experience-20261101-r3`。后者缺少 readelf，启用前检查实际 ldd 解析并执行相同主机密钥预检；核心 SHA-256 两台一致。这里是受控补丁部署，不代表另一个任务未提交的网页或桥改动已经发布。

生产只做 HTTPS 状态、已安装读取控制接口及反馈账号权限拒绝检查，没有制造真实玩家反馈。完整有授权上传、落盘哈希、慢磁盘流控和并发控制请求在隔离真实 C++ 节点中执行。记录位于当前工作树 `build/live-node-verification.json`；测试与客户端报告对应。
