# 房间临时下载加速

节点只核实文件提供者是否有权共享当前房间配置，并签发 5 分钟上传授权。文件下载与按哈希查询公开，无需账号令牌。未公开模组补传后也可被他人获取；启动器必须提示敏感内容不要共享。

节点服务配置：`BUGGCRAFT_ROOM_CACHE_URL=https://mirror.bugg.icu`，`BUGGCRAFT_ROOM_CACHE_ISSUER=default`，`BUGGCRAFT_ROOM_CACHE_SECRET` 为独立生成、至少 32 字符的密钥。密钥只存服务环境，与源站对应发行者的密钥一致，不能提交仓库。未配置时旧版 P2P 流程仍然可用。

新增 `room.request` 操作 `content_cache_grant`，复用原生桥已有透传，不需要重新编译 C++。房主传 `share: true/false` 设置本次会话共享；成员只取得源站地址，不取得上传令牌。授权绑定发行者、房间、配置、模组/资源清单哈希和数量；关闭共享后停止签发，旧授权最长 5 分钟过期。

启动器先提交文件信息，源站决定直下或缓存，只补传源站明确请求的文件。普通玩家只看到“文件共享与临时下载加速”和通常 8 小时的说明，无需知道实体何时清理。缺失队列保留已完成文件与断点，实际来源均不可用时才给出缺失原因。

完整设计、跨房间去重与 TTL 规则、后台配置、验收结果见资源源站项目 `docs/房间客户端文件兜底实施规划.md`。A 房间第 0 小时申请 8 小时、B 房间第 5 小时申请同一文件 8 小时，只存一份实体，最早第 13 小时才可清理；轮询不续期。

部署顺序：源站接口、上传密钥与反代 → 节点环境和 Python 服务 → 启动器开发版。下载不使用上传令牌，GET/HEAD 不附带 Authorization。旧客户端无需变动。
