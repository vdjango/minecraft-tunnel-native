# 统一控制与稳定性

2026-11-11 目录接线：ControlClient 的 rooms/resolve/publish 只适配中心 room/list、room/resolve、room/publish；公开策略不在桥另写副本。Rpc 在房主建立成功以及现有 describe/configure/retarget 后同步节点确认的描述，缓存相同描述避免重复写入；失败不终止游戏会话，下次 describe 重试。中心仅列出已发布且当前房主与节点租期有效的公开条目；邀请秘密仅在有权限的解析/复制邀请路径传输，不进入列表与日志。加入分配携带已有邀请秘密证明，保持 room owner/epoch 固定。

当前接入使用[独立 C++ 控制服务](../../buggcraft-control-native/docs/00-规划总览.md)。北京部署、实测和回退维护在[控制部署报告](../../buggcraft-control-native/docs/10-IP部署与受管接入.md)。旧 Python center/edge 仅保留历史兼容测试，不再按它分发入网票据或联邦主密钥。

## 登录与转发职责

玩家在控制地址完成账号登录、设备批准、刷新和撤销。账号兼容适配器只在控制主机运行，其管理员授权文件不发给节点。C++ 中心验证公开证书、原账号签名的设备委托和设备私钥挑战，维护在线状态、好友、邀请、地区候选与原子容量预留。

`mode=native` 节点无管理/玩家网页，也不构造账号与联邦服务；旧登录、管理、账号、设备和 profile 路径均无路由返回 404，根路径同样为 404。仅保留 proof 和健康 JSON，状态 launcher_login=0、registration_open=false。SSH 仅接纳有效中心身份与分配票据的 host/client，旧账号、共享令牌和 directory 不能绕过中心。精简与复用见[13](13-服务精简与复用验收.md)。

桥 CLI、C ABI SDK 调用同一个 `Rpc/ControlClient`。候选探测只做固定公钥 SSH 握手，不登录目录。房主经中心候选、最多八个有界探测和原子预留获得节点；好友加入固定房间 owner/epoch。未知控制操作明确拒绝，不退回旧登录。游戏字节仍由 Session、SSH/WebRTC 与 C++ 节点核心处理，中心不在每个包路径上。额外压缩默认 off，加密保持开启。

## 节点配置

先按 [03](03-节点部署与配置.md) 初始化，保留生成的 relay/web 配置、独立密钥与持久目录，再配置：

```ini
[control]
mode = native
origin = https://control.example.org
ca_file = control-ca.pem
signing_public_key = <中心64位十六进制Ed25519公钥>
credential_file = control-enrollment
endpoint = relay.example.org:443
proof_endpoint = relay.example.org:443
region = cn-north
operator = unknown
slots = 32
bandwidth = 6000000
```

长期凭证默认不设到期时间，可撤销、轮换、供多节点注册，仅授予 enrollment 权限。每节点独立密钥、身份和短期运行授权，首次所有权验证后保存 `managed-node.json`。重启用自身私钥恢复身份与新心跳 epoch，不复制其他节点状态。注册不等于进入官方候选池，由信任池和可达性规则共同决定。

凭证私密保存，不写源码、命令行、清单或报告。公开安装凭证不能当作管理员秘密或信誉证明。第三方节点不得获得管理员令牌、中心签名私钥、数据库连接或用户保险箱。`[identity]` 只供控制主机，禁止分发给工作节点。

## 生命周期与故障边界

2026-11-12 修复续约公平性：此前每轮固定取 allocations 的前 256 条，并把串行 HTTPS 续约放在心跳任务中；大节点后续成员可能长期轮不到，慢请求还会延迟节点心跳。现在同一 ManagedControl 按预留 ID 轮转，每次最多 256 条，每 5 秒加抖动运行；失败也前移游标。续约与心跳各有一个所属后台任务，共用原上限四条连接的验证 HTTPS 会话，关闭时一并取消。没有新增游戏转发线程或改变数据路径。

新控制接口 placement/refresh 一次接收一批本节点活跃预留/释放 ID，只续活已确认且未过期的分配；首次入场仍必须携带票据走原 confirm。批次不重复发送玩家授权/票据，降低请求次数和节点速率预算消耗。对于没有该接口的第三方旧控制，兼容回退到原 confirm/release，最多四条并发；旧端逐条请求受网络与预算限制，不能承诺其拥有批量接口的同等容量。断开超过 60 秒才释放，入场与释放由既有 admission lock 串行，迟到结果不能删除新入场记录。

600 个模拟活跃预留覆盖轮转与失败前移，阻塞续约时心跳仍执行，关闭两任务测试通过；原生控制隔离 PostgreSQL 验证权限、上限、首次入场不可绕过、释放不可复活，以及原单条确认回归通过。这里是实现正确性验证，不是 600 名真实玩家、公网容量或节点 C++ 迁移验收。当前适配器仍是待迁移 Python，不能据此发布“纯原生节点”安装包。

节点复用有界 HTTPS 连接，严格验证 CA 与主机名；心跳带序号、epoch，失败退避并加入抖动。新入场在线确认分配、检查设备撤销；票据短期有效。预留数量有上限，断线保留 60 秒，桥向中心换取同一预留的新票据；恢复不改变房间归属或增加槽位。关闭房间释放预留。

中心不可达时已有游戏继续转发；新登录、重新入场、分配与社交修改需要中心可用。中心断网与转发节点故障不同；没有复制 TCP 状态，不能承诺节点故障无缝迁移。单台控制机器和数据库仍有单点风险。

好友快照来自中心数据库。收件设备读取有界 inbox 后，桥批量确认 delivered；accepted、delivered、seen 不混淆，不自动冒充用户已读。在线租期失效为 unknown；没有真实世界状态时房间 availability 也为 unknown。

## 验证

`tests/test_service_portal.py` 检查无管理/账号端点与本地账号隔离，`tests/test_managed_control.py` 拒绝旧 SSH 登录。`tests/test_managed_integration.py` 使用真实精简角色、控制程序、节点、桥与 SDK，覆盖邀请、固定分配、断线恢复、载荷/EOF 和中心停止后已有游戏继续传输。

北京公网证据见控制部署报告；本轮没有迁移其他地区的旧联邦节点，不能视为均已移除登录或加入中心。macOS/ARM 实机、跨地区选路、数据库主备和大规模长连接仍需独立验收。
