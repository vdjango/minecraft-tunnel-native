# 跨架构性能优化

优化对象是节点、原生桥和它们共用的 SDK 引擎。性能收益要分别证明，不能把字节扫描吞吐当作公网中继或玩家数量增幅。

## 构建与分派

单配置构建未指定类型时使用 Release；已有 GCC/Clang Release `-O3`、MSVC `/O2` 和 `BUGGCRAFT_LTO` 保留。默认不加 `-march=native`。`BUGGCRAFT_SIMD=ON` 为字节扫描分别编译 SSE2、AVX2、AVX512F/BW 或 AArch64 NEON 内核，并启用固定版本 aklomp/base64 0.5.2 的 AVX2/AArch64 NEON 编解码；普通入口保留目标平台基线。SSE2/AVX2 扫描共用同一内核源码模板；其他内核是同一字母表规则的不同指令实现。

| 目标 | 新字节扫描 | 兼容策略 |
| --- | --- | --- |
| Windows/Linux/macOS x86/x64 | SSE2、AVX2、AVX512F/BW 按 CPU/OS 能力提供 | GCC/Clang CPU builtins；MSVC CPUID + OSXSAVE/XGETBV，不能只检查 CPUID |
| Windows/Linux/macOS AArch64 | NEON 扫描；GCC/Clang 另有 NEON Base64 | 属于这些平台的 AArch64 基线，MSVC 扫描使用 `arm64_neon.h`；该版本第三方编解码在 MSVC ARM64 使用通用实现 |
| Apple 多架构单次构建 | 通用路径 | 不拿宿主架构决定目标指令；通常分别构建 Intel/ARM64 产物 |
| 其他 C++20/OpenSSL 可构建目标 | 通用路径 | 不宣称存在未实现的 SVE/RVV/AltiVec 内核或已验证的发行包 |

自动扫描分派当前优先 AVX2，再 SSE2/NEON，再通用。AVX512BW 通过显式基准入口测量，尚不自动选用；更宽指令不保证交互混合负载更快。MSVC `/arch:AVX512` 可用更多扩展，因此额外要求 CD/DQ/VL。ISA 对象和 Base64 库不参与跨 ISA IPO，防止内联将专用指令带入基线入口。`BUGGCRAFT_SIMD=OFF` 去掉新增 ISA 内核及库的可选 ISA 编解码；启动新进程前设置 `BUGGCRAFT_DISABLE_SIMD=1` 同时关闭新增扫描和 Base64 加速，不关闭 OpenSSL、zstd 或 libc 内部优化。

Base64 库仅在 `.deps/` 保留一份由 SHA-256 校验的上游源码，不复制算法。`encoding.cpp::selected_codec` 调用其固定版本内部 `codec_choose` 一次，保存不可变函数表；直接使用每次调用的流状态与无状态 finalizer，避免其公共 API 的全局可变 codec。升级库时必须重新审查这个内部接口、大小上界、并发与尾部行为。AVX512 编解码需要另一组特性，本次未启用；扫描支持 AVX512BW 不表示启用了 AVX512 Base64。

加密、SHA、压缩和复制复用 OpenSSL、zstd、libssh 与平台库。不要替换为自编密码算法或对整个依赖添加本机 ISA 开关。SDK 动态库与桥可执行程序链接同一引擎，使用同一编码、摘要与运行期分派，无新增 ABI 字段。

## 对照方法

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUGGCRAFT_BENCHMARKS=ON
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
python scripts/benchmark_cpu.py --binary build/buggcraft-cpu-benchmark --rounds 5 --output validation-artifacts/cpu.json
python scripts/benchmark_cpu.py --binary build/buggcraft-encoding-benchmark --rounds 5 --modes auto --output validation-artifacts/encoding.json
```

Windows 可执行文件增加 `.exe`，按构建指南准备相同依赖 DLL 搜索路径。复制旧实现构建产物后，用同一个输入/编译器跑旧版与新实现。不要把未优化的 Debug 当作基线。

`benchmark_cpu.py` 每轮交替模式顺序：`auto` 为新增扫描/编解码和库自动硬件分派；`scalar` 只关新增扫描/编解码；`crypto-generic` 只屏蔽 OpenSSL 能力；`generic` 同时屏蔽两者。掩码只设置在测试子进程，绝不写系统环境或服务配置。x86 使用 `OPENSSL_ia32cap=0:0`，ARM64 使用 `OPENSSL_armcap=0`；这表示关闭 OpenSSL 可选能力，不表示整个程序、编译器和 libc 不含任何 SIMD。其他架构没有验证过的掩码时明确拒绝该对照模式。

CPU 微基准验证 Base64 结果、SHA 摘要与 AEAD 解密/tag，失败的整轮结果无效。扫描基准分别列可用后端，不能强行执行不受支持的 ISA。摘要基准的内存流用于比较重复计算，不是磁盘实测。真实中继继续使用 `scripts/benchmark.py`，固定连接数、AES-GCM、无 SSH 压缩，校验数据与 EOF，并记录服务进程 CPU/RSS 与 RTT。持续负载复用 `scripts/bridge_soak.py`。

```bash
BUGGCRAFT_NATIVE_CORE="$PWD/build/buggcraft-core" python scripts/benchmark.py --engines native \
  --flows 1 8 --mib 64 --rounds 5 --modes auto scalar crypto-generic generic \
  --baseline-core /path/to/baseline-core --output validation-artifacts/relay.json
```

中继掩码仅影响服务端进程树，发流客户端保持硬件加速；`--baseline-core` 可省略，提供时每轮加入原版 Release 对照。`server_cpu_percent` 按一逻辑核 100% 计，RSS 是原生核心与 Python 管理进程之和；吞吐是两个中继出口的载荷合计，RTT 在吞吐阶段后另测。这个脚本的单个 AsyncSSH 发流进程也可能限制吞吐，不能据此宣布节点峰值容量。

至少三轮，报告中位数与范围，保留原始 JSON、二进制 SHA-256、源码快照、构建参数和依赖版本。共享云主机上的背景负载和系统限制造成的噪声应记入报告。`perf` 不可用时使用进程 CPU 计时、符号/代码检索和隔离微基准，不修改生产系统权限以完成测试。

## 正确性与覆盖

### 游戏载荷的加密指令集

`bridge/cipher_policy.*` 在第一次连接前比较当前 OpenSSL 的 AES-256-GCM 与 ChaCha20-Poly1305 EVP 成本：128 B 和 16 KiB，各三组交替测量取中位数。仅大包成本低于 ChaCha 的 85%、小包成本低于其 110% 时，向 libssh 原有允许列表前置 AES-GCM；否则保留原库顺序。此探测是本机调度启发式，EVP 的 ChaCha AEAD 结构并不等于 OpenSSH 的结构，收益必须用真实中继复测。它也不知道对端 CPU 的速度；异构服务器应按同一负载验证。

加密仍由 libssh/OpenSSL 完成，由 OpenSSL 选择 AES-NI/PCLMUL、ARM AES/PMULL 等实现；不全局强制 AVX，不复制密码算法。保持库允许的回退算法和主机公钥/认证校验。`BUGGCRAFT_SSH_CIPHER_POLICY=auto|library|aes-gcm|chacha` 必须在进程首次连接前设置，后两项表示偏好而非禁止回退；未知值保持库默认。现有进程和生产服务不受测试环境变量影响。成功连接日志 `ssh_transport_ready` 及通用 transport 诊断记录实际双向 cipher，不能用策略名称推断最终协商结果。

`scripts/benchmark_forwarding.py` 复用持续负载夹具做三轮交替对照：baseline 为保留的旧二进制，auto 为新默认，scalar 仅关新增字节 SIMD，crypto-fixed 屏蔽原生节点和桥的 OpenSSL 能力并偏好 AES，crypto-auto 同样屏蔽能力但启用自适应选择。auto 与 crypto-fixed 必须核对实际 cipher 相同，才是同算法硬件开关对照；Python 发生器不屏蔽能力。它是回环原生游戏转发合成负载，经过 Minecraft 握手校验，不是原版游戏 GUI，也不是公网容量测试。

```bash
python scripts/benchmark_forwarding.py --output validation-artifacts/game-forwarding \
  --baseline-core /path/to/before/buggcraft-core \
  --baseline-bridge /path/to/before/buggcraft-bridge
```

Windows 参数加 `.exe`，并将完整运行依赖目录放入 PATH；Linux 共享库目录按构建指南设置。报告同时记录已校验的应用回声 MiB/s（每个来回只计一次数据）、CPU 秒/GiB、各玩家 P99、进程 RSS、构建哈希及算法。往返会经过多段加密转发，这些字节不能直接当作网卡流量或玩家人数。

字节扫描测试覆盖所有可能字节、各向量 lane、非对齐地址、尾部长度及保护页；标准 Base64 的 padding/末尾零位检查不因 SIMD 而放松。桥接接入码各自保留旧格式的混合 URL 字母表与 padding 策略，域层限制及错误码不搬进共享编码层。摘要测试包含已知向量、单/双哈希一致性和读失败。

实际测试平台与构建矩阵分开报告。编译通过不是实机测量，模拟 ARM 不是 ARM 性能，CI 配置不是已经运行的 CI 结果。需要针对新的架构提供性能承诺时，必须补相应硬件实测。跨机器解包源码后使用独立构建目录或强制重编译项目源文件，避免归档时间戳早于旧对象导致运行旧实现；通过二进制哈希及符号核实被测版本。
