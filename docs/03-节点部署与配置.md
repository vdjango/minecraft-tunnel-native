# 节点部署与配置

当前节点是无管理网页的受管转发服务，仅接受独立控制服务身份和分配票据。玩家登录控制网址，不填写节点 proof 地址。架构与功能边界见[12](12-统一控制与稳定性.md)、[13](13-服务精简与复用验收.md)。旧发布包可能仍带浏览器初始化，不代表本源码版本。

## 初始化与自动加入

依赖和原生构建见[02](02-构建与发布.md)。从接入控制的运营者取得 HTTPS origin、公开 CA/证书、Ed25519 公钥与长期 enrollment 文件；官方与第三方自建服务使用相同配置，无需改源码。

```bash
python scripts/configure_node.py \
  --directory /var/lib/buggcraft-node \
  --host relay.example.org --port 3333 --proof-port 18443 \
  --control-origin https://control.example.org \
  --control-ca /secure/control-ca.pem \
  --control-key CONTROL_PUBLIC_KEY_HEX \
  --credential-file /secure/control-enrollment \
  --region cn-north --operator example --slots 32 --bandwidth 6000000
```

初始化拒绝覆盖已有配置/密钥，生成独立节点私钥、内部令牌、proof TLS、精简状态、控制 CA 和凭证副本。不生成管理员密码、玩家账号库或联邦 profile。文件仅运行账号可读，目录应为 0700；root 初始化后把所有权交给服务账号。

```bash
export BUGGCRAFT_NATIVE_CORE=/opt/minecraft-tunnel-native/runtime/bin/buggcraft-core
python web/main.py --directory /var/lib/buggcraft-node
```

启动自动进行入网挑战、私钥签名、可达性证明和心跳，保存 managed-node.json；重启以自身密钥恢复。长期凭证默认无到期时间，可撤销轮换，仅授予注册能力。proof 必须可从控制服务访问；注册与可分配资格仍遵循[控制规则](../../buggcraft-control-native/docs/08-构建运行与接口.md)。

新源码构建的 Debian 包使用 `sudo buggcraft-node configure` 加上述参数，然后 `sudo systemctl start buggcraft-node`；status/logs 用于运维，setup 和浏览器设置移除。无配置时安装脚本不反复启动节点。本轮未重新制作/发布 .deb，包装脚本检查不是安装包发布验收。

## 配置与网络

server.conf 的 relay 段负责监听、workers、buffer_kib 和资源上限，web 段只负责 proof/健康 TLS，control 段指定 origin/CA/公钥/凭证、公开 endpoint/proof_endpoint 和地区预算，见[示例](../config.example.ini)。额外压缩默认 off，不关闭 SSH/WebRTC 加密或 Minecraft 自身压缩，见[11](11-转发性能与压缩配置.md)。

默认转发 TCP/UDP3333、proof HTTPS18443；NAT 使用真实映射入口，0.0.0.0 仅表示监听。自签名 proof 证书须由所接入控制明确配置信任，正式部署建议可信域名证书；不能忽略 TLS 错误。

有反向代理时 web.host 可用 127.0.0.1，公网仅转发 /.well-known/buggcraft-node-proof，健康 JSON 按运维需要访问，其他 HTTP 路径无需代理。专用 TCP443 分流模板见 [stream](../packaging/nginx/buggcraft-node-443.stream.conf)、[HTTP](../packaging/nginx/buggcraft-node-443.http.conf)，应按最小路由调整。统一服务同机时，/v1/、账号页分别送控制与身份适配，SSH 始终送转发核心。

node-state.json 可配置 trusted_proxy_enabled/trusted_proxy_cidrs，仅信任真实代理，由代理覆盖地址头；不再从网页更新代理网段。上游 HTTPS 继续验证 CA/主机名，先 nginx -t 再 reload，不覆盖已有站点。

## 运维与切换

```bash
systemctl status buggcraft-node
journalctl -u buggcraft-node -n 80 --no-pager
timedatectl status
```

诊断日志沿现有生命周期有界保存，没有 /diagnostics 网页。源码 systemd 配置独立运行账号、持久目录、WorkingDirectory 与 BUGGCRAFT_NATIVE_CORE，参考[北京实际部署](../../buggcraft-control-native/docs/10-IP部署与受管接入.md)。共享 4 GiB 机器不运行重型编译。

切换控制信任域用新目录/新身份，不能复制旧 managed-node.json、控制 admin token、中心签名私钥或数据库凭据。控制与节点支持同机/异机，权限独立，游戏包不经中心。升级先准备新发布目录并备份，停机切换后验证 proof、心跳、分配和真实载荷，失败回旧发布目录。重启中断现有转发连接，不承诺无缝迁移。
