# 按玩家留存连接日志

节点和原生 C++ 桥现在把连接元数据写入独立 JSONL 文件，路径按玩家身份和会话拆分：

```text
<日志根>/players/<player-id>/<session-id>.jsonl
```

节点默认使用 `~/.local/state/buggcraft/players`，macOS 使用 `~/Library/Logs/Buggcraft/players`，Windows 使用 `%LOCALAPPDATA%\Buggcraft\logs\players`。原生桥也可通过 `BUGGCRAFT_BRIDGE_LOG_DIR` 指定日志根目录。

登录账号使用 SHA-256 截断标识，不把账号名或认证凭据放进目录名；匿名用户按连接生成独立 ID，不会把共用接入码的多人合并。匿名 ID 不承诺跨重连识别同一玩家。

日志记录连接建立和关闭、P2P/中继路径、压缩统计、逐秒流量、流打开与关闭、背压/停顿，以及可用的客户端往返测量。游戏包正文、游戏聊天、密码、接入码和 ICE 凭据不会写入玩家日志。节点诊断页可以按玩家和会话筛选；启动器诊断 ZIP 会在存在原生桥日志时按目录保留这些 JSONL 文件。

节点默认保留 7 天、总量目标 1 GiB，活动会话按 16 MiB 滚动；原生桥默认保留 7 天、总量目标 256 MiB，单文件按 4 MiB 滚动。网络线程只投递到有界队列，磁盘由独立写入线程处理；队列溢出或磁盘错误会计数并告警，日志故障不阻断游戏转发。POSIX 环境下目录权限为 `0700`、文件为 `0600`。

当前桌面启动器的房间数据通路仍运行 Python `TunnelHost` / `TunnelClient`。其现有连接日志保存在 `p2p-sessions/`，C++ 桥的逐玩家日志会在桌面切换到原生进程后由同一个诊断 ZIP 收集；因此不能把现阶段的 C++ 桥日志描述为桌面玩家已经在持续生成。节点端逐玩家日志和管理页不受此限制。

验证覆盖账号与匿名隔离、会话拆分、逐秒采样、流关闭、写队列溢出、磁盘失败恢复、保留期限/容量、滚动文件、符号链接拒绝和诊断 ZIP 白名单。Windows 和 Ubuntu 的 C++ 单测、Ubuntu 17 项原生/桥接/日志测试、桌面 9 项诊断测试均通过。

四个 Mojang 原版 1.21.8 客户端经 Ubuntu C++ 节点测试通过，结果保存在 `validation-artifacts/vanilla-20261023-063244/report.json`：三位访客各自在约 2 秒内从死亡恢复到 20 点生命值，四人移动和方块变化同步、完整客户端重连均通过。节点落盘 6 个互相隔离的玩家/观察会话目录，记录 869 条逐秒采样和 294 条流关闭事件。该原版测试使用 relay 路径。

45 秒三客户端连续流量测试结果见 `validation-artifacts/bridge-soak-45s.json`。每位客户端传输约 244–250 MiB，RTT p99 为 3.27–3.47 ms，最大探测延迟 7.8–12.3 ms，连续传输间隔最大值 21–35 ms。此压力测试是原生桥 relay 的本机回环流，不是公网游戏链路测试。
