# 30 分钟持续高压测试（2026-10-23）

结果：通过。实际负载持续 **1800.217 秒**，测试进程返回 0，所有本次启动的原生进程已退出。

## 测试范围

在 Ubuntu 独立验证目录运行真实 C++ 节点核心、1 个房主桥进程和 3 个访客桥进程，使用真实 SSH 加密中转。Python 负责测试调度、节点控制面和 TCP 回显端点；数据转发经过 C++ 桥和核心。

每个访客同时运行 3 条不限速的 64 KiB 大流和 1 条小包 RTT 探测流。另以约每 0.5 秒一次的频率创建短连接，并发送房间控制请求。第一名访客发送可压缩的重复数据，另外两名发送随机数据，覆盖压缩路径和不可压缩数据的传输。每次回显均校验字节，结束时检查 EOF。

这是同一 Ubuntu 主机回环网络上的传输持续性测试，**没有运行 Minecraft 游戏客户端，也没有覆盖公网 P2P、NAT、Windows/macOS 或死亡复活场景**。此前原版客户端实测与本轮压测是不同验证，不能合并声称完成了 30 分钟原版游戏实测。回显端点、发生器及 Python 调度也会影响吞吐结果。

三个访客分别完成 64.256、60.784、61.275 GiB 左右的已校验回显。共取得 191967 个 RTT 样本。所有数据校验、EOF 和控制请求断言通过，没有在负载运行期间发生意外断流或探测超时。

吞吐是回显应用负载口径：收到并校验一次的负载计一次，双向应用负载再乘二。它不是网卡吞吐、SSH 密文流量或公网带宽。压缩、随机数据比例和回环网络均影响结果，不能据此承诺公网可承载人数。RSS 中位数增加约 1.16 MiB；本轮没有出现明显内存膨胀，但单次 30 分钟结果不足以排除缓慢泄漏。

## 日志观察与后续问题

玩家日志按身份分别保留在节点、房主桥和各访客桥目录中；测试检查了三名访客身份没有被合并，房主和节点均存在各自的流采样、结束事件，日志没有保存令牌、邀请密钥或游戏包内容。36 次背压开始均有结束事件，最长记录为 1.166 ms。

6636 条桥端流结束记录中，4602 条 `clean_eof=true`，2034 条 `clean_eof=false`。后者包含 2027 条短连接和 7 条持续约 1800 秒的连接，长连接均运行到了预定结束，收发计数一致。外部回显与 EOF 断言全部通过，所以这些记录不能直接算作运行中掉线；但也不能声称所有流的关闭状态均正常。

源码中 `clean_eof` 取决于桥本地 `sent_eof && socket_eof` 标志，而 `Session::pump` 可以在观察到 SSH channel 已关闭后直接结束流。现有现象与关闭时序导致标志未补全相符，**尚未通过专项测试确认根因**。后续需要补充明确的关闭原因，分别验证正常半关闭、对端关闭及异常截断；本轮保留原始日志，不改写或忽略该标志。

控制台结束阶段出现 asyncio 慢任务提示，发生于读取完整日志和关闭进程期间；负载阶段的数据块间隔与 RTT 以独立测量结果为准。
