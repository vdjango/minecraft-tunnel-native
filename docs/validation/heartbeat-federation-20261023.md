# 心跳与联邦节点故障隔离（2026-10-23）

本轮修改集中在连接存活探测和联邦控制面的调度。未部署正式服务，测试只使用独立 Ubuntu 验证目录和 Windows 本机随机端口。

## 连接和房间生命周期

桥与节点共用 `core/heartbeat.hpp` 的单调时钟计时器。计数来自 libssh 接收的 SSH 数据包，TCP ACK 不会续期。空闲约 5–6 秒发送标准 SSH keepalive；连接繁忙时不额外发送；20 秒未收到 SSH 数据即结束连接。节点和桥的探测相位错开，待响应探测不会不断堆积。网络线程在既有 poll 循环内执行，未增加每连接线程或每流心跳。

- 访客正常退出或进程被强制终止：释放其连接、流和人数配额，其他玩家继续使用房间。
- 访客/房主网络静默中断：TCP 连接仍存在时，也由 SSH 存活期限发现。日志使用 `heartbeat-timeout`/`heartbeat_timeout`，桥 `session.list.reason` 返回超时原因。
- 房主异常失联：清理其流，将房间置为等待，默认保留 120 秒恢复窗口；同密钥房主重连取消过期任务。超过窗口关闭房间。
- 房主正常结束房间：继续执行已有主动关闭流程。
- 桥已判定网络故障时，不再通过失效 SSH 同步发送关闭请求，避免收尾再等待一次网络超时。

20 秒是探测策略期限；实际观察还受系统调度和事件循环延迟影响，不承诺进程被暂停或主机严重过载时仍准点完成。

## 联邦不依赖入网入口

拓扑 A→B、C→A 完成发现后，B、C 独立保存对方的已验证公钥和入口配置。A 强制退出或主动退网只影响 A 自身：B、C 继续直接同步；A 的公告租期届满后只退出可用目录，不删除其他成员配置，也不传播级联退网指令。

测试在 C 上建立真实 C++ 房主桥、访客桥和持续 TCP 回显流，分别强杀 A 的原生核心、让 A 主动退网，并在每次故障后继续传输超过一个完整公告租期。校验同一连接持续回显、新建流成功、B 可定位 C 的房间、C 房间仍在线。测试不包含原版游戏或公网 NAT。

若 C 尚未从入网入口学到 B，入口此时失效，C 无法凭空发现未知地址。承载在 A 自身的中转 TCP 流也无法无缝转移到 B；本轮保证其他独立节点及其房间不被级联关闭，不实现跨节点游戏会话迁移。

## 限制联邦同步放大

| 项目 | 策略 |
| --- | --- |
| 成员数 | 沿用明确上限 32，未扩展为无限规模 |
| 后台调度 | 每 0.8–1.2 秒一次；启动另有随机错峰 |
| 并发交换 / 出站缓存连接 | 每节点最多 3 / 3，握手先预留容量 |
| 单次交换 | 4 秒总期限；慢节点不阻塞其他交换调度 |
| 失败重试 | 指数退避，约 2–60 秒，加入随机偏移 |
| 成员选择 | 保留健康链路及新成员发现机会，按上次尝试时间轮转 |
| 公告有效期 | 30 秒，同时检查单调时钟接收年龄和签发时间 |
| 目录内容未变化 | 只传带原签名的时间刷新；恢复原公告后验签 |
| 账号/副本目录未变化 | 摘要相同则不重复发送该区段 |
| 日志 | 节点健康状态变化记录 ID、前后状态；失败类型不含凭据 |

固定 fan-out 限制每节点每轮发起的连接数，不代表全网目录字节数完全与成员数无关；每个成员仍需获知其他成员状态。保留单记录、快照和成员数上限，配合增量传输限制开销。管理员操作、账号查询及反馈附件传输有各自协议，它们不计入本轮背景心跳流量测量。

紧凑刷新保留原签名验证，旧版本无版本参数的请求仍取得完整快照。重复公告、过期公告、未知刷新基础和伪造签名均不续期。空账号区段代表没有变化，不代表删除本地账号。

## 验证和复现

```powershell
cmake --build build --parallel 3
ctest --test-dir build --output-on-failure
python -m unittest tests.test_bridge tests.test_native tests.test_federation_resilience tests.test_federation_budget -v
python scripts/check_compatibility.py
python scripts/remote_resilience_validate.py --phase all
```

`remote_resilience_validate.py` 使用已有工作区 SSH 信任，只上传到 `/tmp/buggcraft-native-validation`，保留控制台、构建日志、逐玩家日志和测量 JSON。`--phase scale --skip-upload` 可在已上传相同源码后单独运行 32 节点测试，避免改写正在验证的源码。

覆盖：C++ 心跳边界和繁忙连接抑制探测、节点间计时隔离；静默断网、单向短暂停顿、正常空闲客户端、访客进程强杀、房主恢复和超时；入口节点强杀/退网；并发握手池限额、取消握手释放预算；公平发现、失败退避、签名增量及防重放。上述用例已加入四平台 CI；macOS 本轮没有实机执行。

32 节点测试使用真实 C++ SSH 节点，收敛后同时强杀入网入口在内的 4 个节点，观察 65 秒，要求其余 28 个成员互相可见、保留全部已学习配置、后台任务持续运行，单节点在途交换和连接缓存始终不超过 3。测试只产生联邦控制流量，不等价于 32 个满负载游戏节点。
