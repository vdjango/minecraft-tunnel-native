已完成本地浏览器、隔离 Ubuntu 和正式环境验收。服务器与网页已部署到生产；新版启动器安装包尚未重新发布。

## 页面与功能

- 节点门户、官网默认白色背景和蓝色操作按钮，保留深色切换；下载页同步采用白蓝配色。
- 操作入口统一为“连接启动器”，复制的凭据称为“启动器接入码”，第三方接口说明称为“开发文档”。个人账号和访客入口分别展示。
- 登录后返回原本访问的接入码页或问题提交页。接入码、好友、安全与备份、节点设置、用户列表、邮件服务、反馈管理采用统一布局。
- 用户中心、反馈列表工具栏和空状态均提供明确的“提交问题”按钮。可以首次提交描述时同时上传 ZIP，附件上传失败可保留问题后重试。管理员可下载附件、处理问题并记录修复结果。
- 用户列表提供搜索，长账号 ID 缩短显示，完整值保留在悬停提示中。
- `/network` 独立展示已知节点、地区、存活状态、节点间延迟、带宽负载和可用名额。地区由节点运营者填写；没有配置或测量的数据显示未知。网页延迟的观察点是当前节点，不冒充玩家到节点的 RTT。
- 网卡实时收发带宽移到登录后的后台；匿名 `/api/status` 不再返回原始带宽或容量预算。公开路由提示只保留有限的负载比例及接纳状态。
- 连接诊断按玩家、会话展示断开原因、流量峰值、客户端上报 RTT、背压和节点调度峰值，支持异常定位、时间线和 JSON 导出。默认跟随最新事件，手动回看后刷新保留位置。已用真实 SSH 转发后的日志验证页面筛选及导出。

## 原生桥选路与回退

选路代码位于 `bridge/route_score.hpp`、`route_selector.hpp/.cpp`，通过本机 stdio JSON-RPC 提供给启动器。Python 适配负责启动进程、调用和显示通知。

分数越低越优先：

```text
0.45 × min(RTT / 150 ms, 4)
+ 0.30 × 出口负载比例²
+ 0.15 × 1 / (1 + 剩余名额 / 4)
+ 0.10 × min(抖动 / 50 ms, 2)
```

未知容量带有保守惩罚，不作为零负载。失联、维护或没有访客名额的节点不参与新房间选择；全网满载仍允许读目录，新建房间返回 `-32022`。实际容量由服务端再次校验，提示不构成预留名额。

- 每个导入节点最多探测 6 个固定公钥入口，最多 3 个并发，缓存 30 秒，保留最多 3 个备用。探测使用目录 ping，不进行后台游戏带宽压测。
- 普通优化切换需分数降低超过 20% 且绝对改善大于 0.08，切换后保持 90 秒；失联、维护或容量不可用绕过保持期。失败探测采用 2–32 秒退避。
- 桥提供 `node.selected`、`node.routes`、`node.failed` 和一次性 `bridge.events`。直接请求回退和预先探测切换都会留日志，并由启动器显示非弹窗短提示。
- 入口切换只作用于之后的新连接。已建立的游戏连接继续使用原来的房主和传输，不因目录改选而被主动关闭。真正承载游戏的节点或路径失效时，仍可能需要重新连接，不能把备用入口理解成活动 TCP 无缝迁移。
- 旧安装缺少原生桥、系统拒绝启动、进程异常时回退到已有固定公钥入口列表，并限制重试。错误日志不输出访问凭据。
- 启动器构建可使用 `build.py --native-bridge-dir <CMake安装目录>`，随包保留原生桥、动态库相对路径、许可证和 SHA-256 清单。未打包新桥的旧安装继续使用兼容回退。
