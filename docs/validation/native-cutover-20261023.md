# 原生桥接管验证（2026-10-23）

本记录对应 `0.3.0` 源码及 C ABI v1。启动器默认加载原生动态库，也可调用独立桥进程；两者链接同一 C++ 引擎。Python/Qt 只传递控制 JSON 和显示事件，游戏数据、SSH/P2P、中转、压缩、探测、聊天和整合包传输由 C++ 处理。服务端网页、账号、授权、房间目录和联邦控制业务仍在 Python 中。

Ubuntu 的库测试使用安装后的 `lib/libbuggcraft_bridge.so`，同时覆盖完整安装目录搬迁、中文及空格路径、exe 房主/库访客、库房主/exe 访客、P2P/中转混用、聊天 ACK、个人接入码/好友签名、Mod 分页/哈希失败/取消及并行游戏数据。

此前连续高频控制回归发现后台 presence 占满节点的目录请求预算。已在 C++ 加入前台/后台滑动窗口预算，后台让出额度，前台异步等待；修复后的 exe 和动态库版本均通过 36 次连续控制请求与游戏传输并行回归。

最终 17 节点联邦长链测试在 4.68 秒内收敛；强杀中间 H 节点后，16 个存活节点维持成员关系。连续转发 1499 个数据块、约 93.7 MiB，块 RTT p99 为 10.24 ms、最大 16.26 ms；好友查询没有远端逐级探测，Q 可直接获知 A 的入口并新加入房间。所选目录节点失效后的初次备用入口耗时 135 ms，后续加入耗时 97 ms。该测试为同机真实 C++ 核心和桥、TCP 回显负载，不代表公网游戏延迟。

## 当前短测数据

Windows 使用 4 个 DLL 上下文连接正式节点：1 个房主、2 个强制中转访客和 1 个自动选路访客。每个访客完成 20 轮数据完整性校验，交替发送随机数据和可压缩数据。结果：

| 访客 | 实际路径 | 每轮回显中位数 | 最大值 |
| --- | --- | --- | --- |
| 1 | 中转 | 80.53 ms | 1403.92 ms |
| 2 | 中转 | 82.12 ms | 283.21 ms |
| 3 | P2P | 3.10 ms | 3.83 ms |

这是约 64 KiB 数据块的往返回显耗时，包含首次开流，不是纯网络 ping。样本不足以判断中转峰值原因，也不能据此声称公网持续无卡顿。测试收尾的本地 Python echo 服务有连接重置异常，发生在数据校验完成、原生上下文关闭阶段；它不作为游戏正常退出验收。

同机 Ubuntu 的 8 秒三玩家连续传输测试：每位玩家收到约 42–45 MiB；RTT p99 为 4.44–5.07 ms，最大 15.95 ms，持续数据最大间隙 35.96 ms，没有超过 100 ms 的数据间隙。负载和真实公网游戏不同，不能代替原版 GUI 测试。

原始日志、测量 JSON 和按玩家日志保存在本地 `validation-artifacts/`，不提交凭据和玩家原始日志。测试入口见 `tests/test_bridge_library.py`、`tests/test_bridge_services.py` 和 `tests/test_bridge.py`。

## 路径与接入码边界

发行包保留 `native/bin`、`native/lib`、`native/share`。Windows 通过绝对路径加载 DLL，依赖搜索限于该 DLL 目录及 System32；不修改 Qt、PATH 或工作目录。打包支持仅动态库安装，缺少绑定文件时在替换旧目录之前报错，并拒绝将目标目录自身作为复制来源。Linux 使用 `$ORIGIN`，macOS 使用 `@loader_path`；macOS 静态链接 OpenSSL，避免依赖开发机的 Homebrew 路径。

另用真实 Windows CMake 安装包执行启动器的 `stage_native_bridge`，将生成目录改名搬迁到中文及空格路径。在独立进程中先加载 Qt 6.8.1，令 PATH 仅含 System32、工作目录放置不可用的同名 DLL，再模拟启动器 exe 的发行位置。启动器的库发现和 `NativeRoutes.ensure()` 成功，实际加载搬迁后的 `native/bin/buggcraft_bridge.dll`，未启动桥 exe，`session.list` 返回成功。此项验证实际依赖文件及启动器调用代码，不等于已经重新制作和验收完整 Nuitka 发行包。

`buggnode1-` 是节点接入码：启动器把它交给 `node.add`。匿名码支持联机；个人码另外携带账号委托签名，可调用好友操作。`bugg1-` 是房间邀请码：只交给 `room.join`。桥会拒绝格式不对的码，不会把个人凭据写入 stderr 或玩家日志。

格式错误和运行库/应用控制策略错误分别提示，不会回退到 Python 网络实现。

## 验证限制

当前 Windows 应用控制策略曾阻止本机核心 exe，故完整服务端回归在 Ubuntu 执行；当前桥 exe、动态库及纯 C 消费者可以运行。动态库同样可能被系统策略限制，未提供受信任代码签名或 Apple 公证。

macOS 已配置 ARM64/Intel CI，尚无本次实机结果。本次没有重跑原版 GUI、死亡/复活场景或 30 分钟压力测试，也没有将历史记录重新归因到本次版本。既有多原版客户端、长时间压力、联邦长链和带宽测量保留在 `docs/validation/`，应按当时源码、机器和负载解释。
