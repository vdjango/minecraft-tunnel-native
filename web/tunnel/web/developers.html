02 / QUICK START

用 JSON-RPC 启动桥接进程

每行发送一个 JSON-RPC 2.0 请求，每个请求对应一行响应。先初始化协议，再添加节点，之后创建或加入房间。

  1. 下载并启动桥接程序

    从 Package bridge 下载对应系统的产物，解压后随启动器保留完整目录。通过子进程启动 buggcraft-bridge.exe（Windows）或 buggcraft-bridge（Linux/macOS），重定向输入输出；不需要 Python 环境或语言专用 SDK。

  2. 初始化并导入节点

    调用 bridge.initialize，再用 node.add 导入用户从可信节点取得的接入码。桥接进程负责凭据，不要把凭据写入日志。

  3. 连接房间

    用 room.list 读取公开目录。当前桥接加入接口需要邀请码：让用户输入后调用 room.join；room.host 创建邀请码房间。加入者可以选择 P2P 优先或仅中继。

  4. 启动游戏并清理会话

    把返回的 127.0.0.1:端口 交给 Minecraft。退出时调用 room.close；进程关闭时会清理剩余会话。

# 构建信息: buggcraft-bridge --version

桥接接口的版本边界

标准报文采用 JSON-RPC 2.0；方法名、参数、限制和错误码由 Buggcraft 的 v1 profile 定义。不支持 batch 或状态通知，可用 session.list 刷新状态。运行时保留完整发行目录，当前产物未提供受信任签名或 Apple 公证。查看桥接发行与接入说明。

03 / DIRECTORY

查询节点与房间

公开状态走 HTTPS。桥接接口提供有凭据的目录操作；游戏数据不经过目录查询接口。

目录能力
接口用途
GET /api/status读取节点公开状态、地区、接纳提示、在线人数和注册开关。
node.add验证并导入接入码，返回进程内使用的不透明节点句柄。
node.selected / node.routes（原生桥）读取综合延迟、负载及剩余名额选出的入口和备用线路。
bridge.events（原生桥）读取并消费线路切换提示，使用非弹窗提示告知用户。
room.list分页获取公开房间；传入 offset，最多返回 50 项。
session.list读取本进程活动会话及当前连接状态。
account_lookup（原生 SSH）个人身份可按用户名或账号 ID 查询；不属于当前 JSON-RPC 方法，匿名凭据没有好友查询权限。

限流与错误

单行输入上限 8 KiB；错误使用 JSON-RPC 标准错误结构。超时、节点不可达或凭据失效时提示用户，并采用有上限的退避重试。

节点故障

其他联邦入口可以继续提供目录。房间归属节点不可用时房主需重建房间；已经建立的 Minecraft TCP 会话不会自动迁移到另一台服务器。

04 / GAME CONNECTION

同一房间可以混合使用 P2P 和中继

路径由每位加入者分别选择和协商。一个访客 P2P 失败或主动选中继，不会让房间里的其他访客改变路径。

room.hostnode、game_port、transport、可选 game_directory；返回会话 ID、邀请码和房间状态。传入 Minecraft 实例根目录后，桥扫描其中的 mods 并发布模组摘要。

session.list返回本进程中的活动会话、角色与当前传输状态。

连接方式

transport:auto（默认）会先尝试 WebRTC ICE / DTLS / SCTP 直连，连不上时该玩家自动走 SSH 中继。transport:relay 会跳过 P2P，仅使用中继。

网络边界

P2P 需要双方网络允许 ICE 建连；对称 NAT、防火墙、UDP 阻断等环境可能只能中继。当前节点提供 STUN 地址发现和流量中继，不提供 TURN 服务，也不能保证所有网络都可直连。

隐私与路径选择

P2P 建连会让通信双方获知彼此的网络候选地址。若用户不愿向房间对端提供自己的网络地址，选“仅通过节点中转”。中继能隐藏玩家之间的直接地址，但中继节点仍会看到连接端点和转发流量。

05 / MODS & GAME PROFILE

房间可以核对 Minecraft 版本与模组

房主可发布版本信息和 JAR 清单，访客可查看并选择下载。桥负责校验与传输，是否安装、启用或重启游戏由启动器决定。

房间信息

房主的 game_directory 指向 Minecraft 实例根目录；桥扫描其 mods 子目录，并把模组数量、清单 SHA-256 和最多 24 个 JAR 预览写入房间信息。Minecraft 版本、协议号、加载器和加载器版本仍由启动器通过 settings.game 或 room.retarget 提供。

完整模组清单

如果创建房间时没传 game_directory，房主可在 game_port:0 等待阶段调用 mods.configure 并传入实例根目录。桥扫描最多 1000 个 JAR；访客调用 mods.manifest，每页最多 50 项。

模组传输接口
方法用途
mods.configure房主等待游戏启动时配置 Minecraft 实例根目录；桥读取其中的 mods 子目录并更新房间摘要。游戏端口启用后不能更改。
mods.manifest读取目录。房主本地分页返回；访客先得到 transfer ID，再用 mods.status 轮询并分页读取。
mods.fetch访客提交清单项及本机目标路径下载 JAR；单文件上限 2 GiB，最多 4 个并行传输。收到文件后桥再次核对 SHA-256，再写入目标目录。
mods.status / mods.cancel查询传输进度或取消传输。
不会自动修改游戏

模组清单会自动同步给节点目录，用于显示和比对；版本号、协议号与加载器信息由启动器提供。桥不会替用户安装模组、覆盖已有文件、切换加载器或自动重启 Minecraft；启动器应先展示差异并取得用户操作，再决定下载目标目录。

跨节点用户名搜索

联邦节点同步公开用户名、账号 ID 和公钥。用户名目录不包含密码；查询结果不代表已经获得好友或房间权限。

登录与备份

跨节点登录需要用户启用并配置加密身份备份。没有备份时，账号登录仍依赖注册节点在线；仅同步用户名不能恢复账号。

高级接入：SSH 目录协议示例，需要个人身份授权；当前不属于 bridge 的 JSON-RPC 方法
{"op":"account_lookup","identifier":"alex"}
个人启动器接入码是授权凭据

新版接入码只包含签发节点的 HTTPS 地址和随机兑换引用，不再把节点连接配置直接编码进字符串；桥通过 HTTPS 兑换，最长有效 7 天。旧版接入码仍可导入。兑换后桥仍需取得节点连接地址，因此这不是端到端隐藏服务器地址的加密方案。持有该码的设备可代表账号操作；使用系统安全存储保护接入码，不要写入日志或公开配置文件。

07 / CODE EXAMPLES

各语言复用同一个接口

下列为应用内调用片段；接入码、邀请码和游戏启动函数由你的启动器提供。C/C++ 例子中的 BridgeProcess 是启动器自身的双向进程管道封装，Java 例子使用 Jackson，C# 使用 System.Text.Json。协议请求的格式和顺序相同。

Pythonsubprocess + JSON
import json, subprocess
p = subprocess.Popen([bridge_path], stdin=subprocess.PIPE,
                     stdout=subprocess.PIPE, text=True, encoding="utf-8")
def rpc(i, method, params):
    p.stdin.write(json.dumps({"jsonrpc":"2.0", "id":i,
        "method":method, "params":params}) + "\n")
    p.stdin.flush(); reply = json.loads(p.stdout.readline())
    if "error" in reply: raise RuntimeError(reply["error"]["message"])
    return reply["result"]
rpc(1, "bridge.initialize", {"protocol":1})
node = rpc(2, "node.add", {"code": access_code})["node"]
room = rpc(3, "room.join", {"node":node, "invite":invite, "transport":"auto"})
launch_minecraft(room["address"])
rpc(4, "room.close", {"session":room["session"]})
C / C++OS pipes + nlohmann/json
// Use CreateProcess pipes (Windows) or pipe/posix_spawn (Unix) for the bridge process.
// Keep stderr separate; write_line/read_line exchange one UTF-8 JSON frame each.
#include <nlohmann/json.hpp>
using json = nlohmann::json;
json rpc(BridgeProcess& bridge, int id, const char* method, json params) {
  json request={{"jsonrpc","2.0"},{"id",id},{"method",method},{"params",params}};
  bridge.write_line(request.dump());
  auto response=json::parse(bridge.read_line(8192));
  if (response.contains("error")) throw std::runtime_error(response["error"]["message"].get<std::string>());
  return response.at("result");
}
auto init=rpc(bridge,1,"bridge.initialize",{{"protocol",1}});
auto node=rpc(bridge,2,"node.add",{{"code",access_code}}).at("node");
auto room=rpc(bridge,3,"room.join",{{"node",node},{"invite",invite},{"transport","auto"}});
launch_minecraft(room.at("address").get<std::string>());
rpc(bridge,4,"room.close",{{"session",room.at("session")}});
JavaProcessBuilder + Jackson
var process = new ProcessBuilder(bridgePath).start();
var in = new java.io.BufferedWriter(new java.io.OutputStreamWriter(process.getOutputStream(), java.nio.charset.StandardCharsets.UTF_8));
var out = new java.io.BufferedReader(new java.io.InputStreamReader(process.getInputStream(), java.nio.charset.StandardCharsets.UTF_8));
var json = new com.fasterxml.jackson.databind.ObjectMapper();
var sequence = new java.util.concurrent.atomic.AtomicInteger();
java.util.function.BiFunction<String, java.util.Map<String,Object>, com.fasterxml.jackson.databind.JsonNode> rpc = (method, params) -> {
  try {
    var q=java.util.Map.of("jsonrpc","2.0", "id",sequence.incrementAndGet(), "method",method, "params",params);
    in.write(json.writeValueAsString(q)); in.newLine(); in.flush();
    var reply=json.readTree(out.readLine());
    if (reply.has("error")) throw new RuntimeException(reply.get("error").toString());
    return reply.get("result");
  } catch (java.io.IOException e) { throw new RuntimeException(e); }
};
rpc.apply("bridge.initialize", java.util.Map.of("protocol",1));
var node=rpc.apply("node.add", java.util.Map.of("code",accessCode)).get("node").asText();
var room=rpc.apply("room.join", java.util.Map.of("node",node, "invite",invite, "transport","auto"));
launchMinecraft(room.get("address").asText());
rpc.apply("room.close", java.util.Map.of("session",room.get("session").asText()));
C#Process + System.Text.Json
var start = new System.Diagnostics.ProcessStartInfo(bridgePath) {
    RedirectStandardInput=true, RedirectStandardOutput=true, UseShellExecute=false, CreateNoWindow=true };
using var bridge = System.Diagnostics.Process.Start(start)!;
async System.Threading.Tasks.Task<System.Text.Json.JsonElement> Rpc(int id, string method, object parameters) {
  var q=System.Text.Json.JsonSerializer.Serialize(new { jsonrpc="2.0", id, method, @params=parameters });
  await bridge.StandardInput.WriteLineAsync(q); await bridge.StandardInput.FlushAsync();
  using var doc=System.Text.Json.JsonDocument.Parse((await bridge.StandardOutput.ReadLineAsync())!);
  var root=doc.RootElement; if (root.TryGetProperty("error",out var error)) throw new Exception(error.ToString());
  return root.GetProperty("result").Clone();
}
await Rpc(1,"bridge.initialize",new { protocol=1 });
var node=(await Rpc(2,"node.add",new { code=accessCode })).GetProperty("node").GetString();
var room=await Rpc(3,"room.join",new { node, invite, transport="auto" });
LaunchMinecraft(room.GetProperty("address").GetString());
await Rpc(4,"room.close",new { session=room.GetProperty("session").GetString() });

08 / RELEASE CHECK

上线前逐项验证

请在自己部署的节点上完成端到端测试，并明确告诉用户连接状态和路径。

  • 验证 SSH 节点公钥和 HTTPS 证书；身份不匹配时中止连接。
  • 接入码放入操作系统安全存储；日志隐藏 token、邀请码和签名私钥。
  • 本地游戏地址仅监听回环接口；房间退出后释放端口与后台任务。
  • 测试 P2P 自动连接、P2P 失败回退、仅中继和同房间混合连接。
  • 测试容量上限、邀请码错误、节点失联、登录过期、匿名用户权限和好友双方确认。
  • 说明中继不会使房间会话自动迁移；节点恢复或更换后需重新加入。
