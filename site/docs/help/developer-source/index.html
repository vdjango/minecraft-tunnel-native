源站接入：目录、搜索、译文与制品事实

区分元数据查询、搜索与文件分发，按现有源站接口接入，避免误用管理凭据。

更新于 2026-11-11 · BUGG 项目维护者

本篇目录目录元数据网关搜索结果与包内事实分别使用元数据可查，不等于文件可分发接入自己的源站

01目录元数据网关

只读 GET /v1/catalog/modrinth/search 保留 Modrinth query、facets、offset、limit；GET /v1/catalog/curseforge/mods/search 保留 CurseForge gameId、classId、gameVersion、categoryId 和分页。

项目详情和版本沿用对应平台路径。游戏版本与加载器过滤由官方参数表达，不把项目简介当作包内依赖证据。上游 Key 留在服务器。

curl --fail --get \
  --data-urlencode "query=sodium" \
  --data-urlencode "limit=10" \
  https://mirror.bugg.icu/v1/catalog/modrinth/search

02搜索结果与包内事实分别使用

GET /api/v1/search、/api/v1/search/capabilities 提供全文或语义搜索能力与实际覆盖信息；GET /api/v1/projects/{provider:id}/similar 提供相似项目。具体可用能力以目标部署返回为准。

包内声明来自完整 JAR 的校验、受限读取与解析。管理端 /api/v1/artifacts/{sha256}/dependencies 返回有证据的声明；它不是兼容性结论，也不是自动安装清单。

03元数据可查，不等于文件可分发

目录网关不会在请求中执行下载、解压、翻译或依赖求解。文件使用源站已公布的实际下载地址与校验值；不得把任意上游 URL 作为公开代理输入。

请求保留超时、取消、分页与错误语义。搜索与带身份的管理响应遵守 Cache-Control，不因 CDN 命中绕过鉴权。

04接入自己的源站

启动器使用同一个可配置源站基址。自建时配置服务器自己的上游授权、公开 HTTPS 和相关分发权限，再逐项验证分类、中文搜索、版本、下载与哈希。

示例展示接口形状，目标域名是否启用某个可选功能以实际能力响应为准。管理与采集接口需要独立权限，不能在玩家应用中嵌入管理员令牌。
